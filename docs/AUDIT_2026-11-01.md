## What was inspected

- `Brof14/ByMeVPN-site` main (`index.html`, `README.md`, repository tree).
- `Brof14/ByMeVPN-app` V2 UI components, theme, `TrialScreen.kt`, `PricingScreen.kt`, `HomeScreen.kt`.

## Findings by priority

### CRITICAL

1. **Unverifiable promises in the original website**: meta description says `No-logs`, `до 10 Гбит/с`, fully anonymous; site also has `15+ стран`. Without infrastructure and independent measurement these must not be marketed as established facts.
2. **Trial model conflict:** `ByMeVPN_bot/constants.py` still contains `INTRO_TRIAL_PRICE_RUB = 1`; Android V2 `TrialScreen.kt` clearly says 3 days free, no card; Windows release-blocker doc also says 0 ₽ no card. The new website adopts **free trial** but backend production compatibility must be checked before deployment.
3. **Production readiness is not established:** Android payment UI uses server-confirmed plans; Windows docs explicitly describe real network tunneling and payment integration as release-blocked. Site must not present all apps as generally available.

### HIGH

4. Old website visual tokens conflict with mobile. Replace gradients, borders, typography, header, buttons.
5. Old headline `Прорви блокировку` and technical hero cards do not explain the product workflow; use direct service promise, supported trial, single CTA.
6. Tariff disclosures: display both total upfront charge and monthly equivalent for long plans; 2/5/10-device tiers differ. Avoid implying the 59 ₽ equivalent is a monthly-billed plan.
7. The old site is a 36kB monolithic HTML with CSS and script inline. Extract to independently cached files. Heavy SPA framework not necessary.
8. Mobile app screenshot: account page shows `Ваш тариф: Не указан` and device row says `Лимит не получен от сервера`. Distinguish missing backend data from factual zero/unknown values; users should see a retry, not an empty or misleading state.
9. Mobile app screenshot: server card shows `Germany-1 · VLESS TLS` twice in technical badges. Surface a human-readable location first and move protocol into advanced details.
10. Registration/login screenshots have different hero positioning and legacy Telegram card occupies substantial space. Consider compact account recovery flow and stable spacing, but do not change auth without functional requirements.

### MEDIUM

11. Source website uses font-awesome CDN and large old canvas animation for decorative purposes; replace with CSS/semantic content, protect reduced-motion users.
12. No structured automated checks in the four-file website baseline; add dependency-free static tests and CI.
13. Website lacks explicit available-vs-coming-soon platform differentiation.
14. Link destinations should make sense before desktop apps ship; bot is the verified onboarding destination.
15. Localization: Android V2 supports RU/EN by source; website has RU only. Full website localization remains a follow-up, not silently claimed done.

### LOW

16. Prefer local and versioned icon/logo asset rather than raw.githubusercontent.com external hotlink before launch.
17. Add verified privacy/legal links once published, without inventing pages or policies.
18. When analytics infrastructure exists, track CTA → bot → activation → first successful connection → payment (with consent where needed).

## Implemented in the review branch

- New semantic website source split into HTML, CSS, JS.
- Aligned source-based palette and web typography with Android V2.
- Hero with clear value proposition, free-trial CTA, explicit eligibility.
- Accessible navigation with skip link, mobile menu, focus-visible, escape close.
- Product showcase based on app UI, labeled visual demonstration.
- Simplified benefits, onboarding, platform availability and FAQs.
- Source-based 2-device plan prices from the bot's current constants:
  - 1 month (30d) 89 ₽ total
  - 3 + 1 months (120d) 316 ₽ total
  - 6 + 2 months (240d) 552 ₽ total
  - 12 + 3 months (450d) 885 ₽ total
- Price note says checkout must verify live pricing.
- 3-day free trial is not described as automatically recurring.
- Removed old unverified anonymity/speed/location claims.
- Added static contract tests / CI (results must be checked after GitHub Actions runs).

## Release gate — do not skip

1. **Verify live bot and VPS trial configuration**; free vs paid discrepancy is unresolved until runtime is inspected.
2. Verify new user activation works end-to-end and is provisioned before showing success.
3. Verify price/terms against actual backend checkout and YooKassa.
4. Verify app illustration points at real approved asset and that raw GitHub image URLs load reliably; vendor local assets if possible.
5. Run website locally and capture screenshots at desktop/mobile sizes. Fix visual overflow and keyboard issues.
6. Run automated checks in GitHub Actions and review any failures.
7. Perform Lighthouse measurements under representative connection/device; no scores were measured in this change.
8. Add legal/privacy links only when real documents exist and are approved.
9. Review A/B hypotheses after sufficient real traffic; do not claim uplift before measurement.
10. Merge PR only after human review and rollout approval.
