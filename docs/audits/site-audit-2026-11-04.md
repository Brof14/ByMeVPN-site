# ByMeVPN — предметный аудит сайта, 4 ноября 2026

**Объект:** `Brof14/ByMeVPN-site`, ветка `main` после слияния PR #4 (2 ноября 2026).  
**Источник фактов:** исходные `index.html`, `styles.css`, `app.js`, `tests/`, README репозиториев `ByMeVPN-app` и `ByMeVPN_bot`, `constants.py` бота.  
**Ограничение:** текущий публичный домен не открылся через доступный удалённый веб-инструмент; ниже кодовые находки, а не результаты Lighthouse или визуальная экспертиза текущего production-рендера.

## Приоритет P0 — что действительно ломало сайт

1. **Незакрытый `:root` в styles.css.** После `--tone-0729ae0e` отсутствовала `}`, число `{`/`}` не совпадало (373/372). В современных браузерах это меняет контекст последующих правил CSS nesting и приводит к непредсказуемому применению селекторов. **Исправлено:** закрыт блок, добавлен регрессионный тест парности скобок и закрытия `:root`. После изменений 422/422 перед добавлением финального правила CTA.
2. **Нет рабочего CTA в hero.** На первом экране единственная заметная кнопка была `disabled` («Скачать для Android»), второй элемент лишь скроллил к демо. Рабочий Telegram CTA глубоко в секции «Как начать». **Исправлено:** первый экран и header ведут в официальный `https://t.me/ByMeVPNbot`; disabled Android download остаётся только в соответствующей секции.
3. **Путаница между макетом и действующим VPN.** Статическая фраза телефона «Нажмите, чтобы подключиться», JS «Устанавливаем туннель»/«Соединение с сервером проверено» создавали ложное ощущение живого туннеля на сайте. **Исправлено:** явное обозначение демонстрации, нейтральные состояния без сетевых утверждений.

## P1 — продукт и conversion funnel

4. **Неверное позиционирование:** title/description/OG описывали исключительно Android-приложение, которого ещё нет в публичном релизе. **Исправлено:** метаданные позиционируют существующий сервис, canonical, robots, OG image и Twitter card добавлены.
5. **Неочевидный порядок действий:** на странице отсутствовала чёткая логика «открыть бот → проверить условия → следовать инструкции». **Исправлено:** компактный onboarding strip, сквозной CTA после продуктовых возможностей.
6. **Тарифы без конкретного сценария:** секция содержала только предостережения о суммах. В конфигурации бота предусмотрены варианты 2/5/10 устройств, но production-данные из API не проверены; **исправлено частично:** перечислены варианты без статичных цен, усилен переход к фактическому предложению бота. **Остаётся:** связать публичную таблицу цен с проверенным backend-источником, если есть авторизованный публичный API.
7. **FAQ не отвечает на главный вопрос:** много про недоступный APK и мало про получение доступа сегодня. **Исправлено:** первым вопросом добавлен прямой сценарий Telegram.
8. **Актуальность Android:** `ByMeVPN-app/README.md` прямо указывает на активную разработку, отсутствие production-ready consumer release и незавершённые платежи/подпись/сетевые проверки. **Не изменять:** disabled Android download, не подставлять debug APK под релиз.

## P1/P2 — интерфейс и доступность

9. **Герой слишком долго не даёт практической пользы:** большая сценография отодвигала единственное действие в боте на несколько экранов. **Исправлено:** компактный работающий CTA в первом экране, более ясный заголовок и подсказки.
10. **Сложная зависимость четырёх sticky scroll-сцен от JS:** правки `story-track`, grid row/высот или `activateScene()` могут снова вызвать пустые блоки. **Сохранено:** структура четырёх сцен, ручной выбор, текущие scroll- и visual QA тесты.
11. **Motion/fallback:** JS добавляет `.reveal-enabled` только при рабочем IntersectionObserver и без reduced-motion; базовые `[data-reveal]` видимы. Это разумный fallback. **Сохранено.**
12. **Навигация:** 5 пунктов + новый CTA могут переполнить промежуточный desktop breakpoint; **добавлены** уплотнение gap на 761–960px и адаптивная полноширинная кнопка в мобильном меню.
13. **Контраст CTA:** базовый hover-селектор навигации мог сделать mint текст на mint кнопке. **Добавлен** отдельный более специфичный селектор с тёмным текстом.
14. **Кнопки и клавиатура:** исходный макет использует `aria-pressed`, live region, Esc, видимые `:focus-visible` контуры и `<details>`; изменения сохраняют эти контракты. **Остаётся:** независимый аудит скринридером и мобильных touch targets на реальном устройстве.

## P2 — техническое качество

15. **CSS maintainability:** ~49 KB CSS до изменений с большим числом хешированных `--tone-...` переменных. Это снижает управляемость дизайн-системы. **Не удаляли автоматически:** массовая подстановка цветов без визуальной регрессии рискованна; последующий рефакторинг под semantic tokens.
16. **Перформанс:** брендовый PNG `assets/brand/bymevpn-shield.png` ~702 KB; используется как иконка в нескольких местах (кэшируемый, но для первого визита тяжёлый). **Остаётся:** предоставить оптимизированные идентичные WebP/AVIF/PNG исходя из мастер-лого с проверкой качества; не заменять чужим значком.
17. **Избыточность сценария:** большая длина `#product` (4 × 66svh на desktop, 4 × 94svh на mobile) при повторяющихся состояниях. **Сохранено** из-за дизайна и прежних автотестов; необходим UX A/B тест (короткая галерея vs scroll storytelling).
18. **Тесты были слишком привязаны к дизайну:** жёсткие проверки числа FAQ, кнопок и reveal-элементов приходится менять при расширении продукта. **Обновлены** контракты и добавлены проверки новых критичных требований. Дальнейший шаг — больше поведенческих тестов, меньше проверок точного количества блоков.
19. **Метрики и production:** отсутствуют подтверждённые измерения Core Web Vitals, реальная платёжная воронка, сегменты пользователей, error monitoring и screenshot QA свежего продакшна. **Не заявлять 100/100 без этой проверки.**

## Приёмка (проверить на PR до merge)

1. `python3 -m unittest discover -s tests -v` — статические контракты.
2. `node --check app.js` — JavaScript синтаксис.
3. `npm ci && npx playwright-core install --with-deps chromium && npm run test:browser` — четыре сцены и все responsive/fallback проверки.
4. Визуальная ручная QA на 320, 390, 768, 900, 1440, 1920px: CTA виден в начале, герой без horizontal overflow, меню, FAQ, demo controls и reduced motion.
5. В отдельной production-среде — Lighthouse + Web Vitals, проверка ссылок, OG preview, сетевых ошибок и реального onboarding бота.

**Решение:** не сливать PR автоматически, пока визуальный результат и CI не проверены. В репозитории сохраняется статический сайт без прямой связи сайта с API и без выдуманного Android-релиза.
