# Дизайн-система ByMeVPN

## Основание

Сохраняем реальные цветовые значения из `app/src/main/kotlin/com/example/bymevpn/theme/Color.kt` Android-репозитория. Атмосферу Hallmark **Midnight** адаптируем к этой идентичности; чужой синий сигнал темы не переносим. В CSS каждое значение цвета и семейство шрифта задаётся токеном.

## Цвета

| Токен | Значение | Применение |
| --- | --- | --- |
| `--color-canvas` | `#090F1D` | Основной фон |
| `--color-surface` | `#121C2B` | Экран приложения, нижние области |
| `--color-surface-raised` | `#172536` | Выбор/фокусируемая поверхность |
| `--color-surface-high` | `#18283A` | Один повышенный уровень |
| `--color-rule` | `#263647` | Разделители и границы |
| `--color-accent` | `#69D3BC` | Одно главное действие и состояния фокуса |
| `--color-accent-ink` | `#0A2431` | Текст на мятной кнопке |
| `--color-ink` | `#EEF4F4` | Заголовки и основной текст |
| `--color-muted` | `#9CACBD` | Вторичные пояснения |
| `--color-soft` | `#7D94A8` | Подписи интерфейсных деталей |

Мятный остаётся сигналом, не заливкой экранов. Градиент сохраняется только в локальном оригинальном знаке приложения; декоративных CSS-glow и цветных ореолов нет.

## Типографика и композиция

- Заголовки: локально подключённый variable display grotesk, Mona Sans 300 с расширенной шириной; корпус: Mona Sans 400. Если источник шрифта недоступен, использовать `Arial`/системный fallback без блокировки текста.
- 16 px — минимум для основного текста. UI-подписи имеют размер, читаемый на телефоне; мелкий текст не несёт условий тарифа.
- Контейнер центрирован, до 1320 px; gutters 24 px на телефоне, 48 px на планшете и 64 px на широком экране. Сетка 12 колонок от 1024 px, ниже композиции перестраиваются в один столбец.
- Первый экран строится асимметрично вокруг большого Android-экрана; на мобильном сначала заголовок, короткое пояснение и CTA, затем экран приложения.
- Интерфейсные поверхности наследуют настоящие скругления Android-компонентов; маркетинговые секции не набиваются независимыми карточками.

## Изображения

- Локальный знак из Android-репозитория, не внешний hotlink.
- Одно оригинальное абстрактное фото/фактура используется только как вторичная глубина в hero; без текста, лица или UI. Оптимизированный WebP и `srcset`/размеры.
- Основной интерфейс собран в HTML/CSS по исходнику Android. Экран размечен как демонстрация в разработке; не выдаёт примерный контент за production-сервер.
- SVG-иконки без emoji. OG-preview собран из собственных текстовых элементов и брендовых токенов.

## Движение и состояния

- Один вход hero на 420–600 ms, только `opacity` и `transform`.
- Продуктовое состояние переключается по явному действию; смена статуса длится около 220 ms и не запускает сетевой код.
- Никаких автокаруселей, параллакса, блокировки скролла и бесконечного свечения.
- `prefers-reduced-motion: reduce` снимает все декоративные переходы; весь текст и оба состояния остаются доступны.
- Все ссылки, кнопки, disclosure-элементы и меню имеют видимый `:focus-visible`; клавиша Escape закрывает меню/диалог.

## Компоненты

1. **Навигация:** фирменный wordmark-ссылкой, 3 внутренних ссылки и один CTA. На телефоне кнопка с понятными `aria-label`/`aria-expanded`; меню изначально закрыто.
2. **App stage:** один большой телефонный экран; рядом status caption «Android-приложение в разработке» и disclosure о демонстрационном состоянии.
3. **Переключатель:** текстовая segmented-кнопка «VPN выключен / VPN запущен»; статус продублирован доступным текстом, а не только цветом.
4. **Путь в бота:** один основной CTA. Для внутренних переходов используются якоря, внешние ссылки открываются с `rel="noopener noreferrer"`.
5. **Условия:** показывает посетителю, что цена, сроки, лимит устройств, trial и автопродление проверяются на экране текущего предложения в официальном боте.
6. **FAQ:** нативные `details/summary`, раздел поддержки и короткие ответы без неподтверждённых обещаний.

## Производительность и доступность

- Без новых runtime-библиотек и видеофона. Первое изображение локально, с width/height, WebP до 500 KB.
- Семантические заголовки, контраст не ниже WCAG AA для текста, hit target меню/кнопок от 44 px, touch layout без горизонтального скролла.
- Текст интерфейса в DOM, корректный focus order, клавиатурное управление, reduced motion.
- Проверки: desktop 1280/1440/1920; mobile 360/390; промежуточный 768; состояние меню, состояния демонстрации, FAQ, ссылки, консоль и измерение горизонтального переполнения.
